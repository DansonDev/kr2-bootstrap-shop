# Bootstrap Shop — КР №2

Учебный интернет-магазин по дисциплине «Фронтенд и бэкенд разработка».

**Тема:** «CSS-фреймворки: разработка интерфейса на Bootstrap или альтернативном CSS-фреймворке».

[Открыть сайт на GitHub Pages](https://dansondev.github.io/kr2-bootstrap-shop/)

Проект выполнен в отдельном репозитории на основе практических работ №9–11. Используются HTML, CSS и Bootstrap 5.3.8.

В практике №9 создана главная страница на Bootstrap-сетке, в №10 добавлены страницы и компоненты, в №11 выполнена итоговая проверка КР №2.

## Страницы

| Файл | Содержание |

## Подключение Bootstrap

Bootstrap **5.3.8 подключён локально**, как предусмотрено дополнительным заданием КР №2. На всех страницах сначала подключается Bootstrap, затем стили проекта:

```html
<link href="vendor/bootstrap/css/bootstrap.min.css" rel="stylesheet">
<link rel="stylesheet" href="css/custom.css">
<link rel="stylesheet" href="css/extra.css">
```

Перед `</body>` подключён JS Bundle:

```html
<script src="vendor/bootstrap/js/bootstrap.bundle.min.js"></script>
```

На страницах каталога и заявки после JS Bundle подключён `js/extra.js` для уведомления о заполнении формы.

Файлы Bootstrap взяты из [официального релиза 5.3.8](https://github.com/twbs/bootstrap/tree/v5.3.8/dist). Лицензия сохранена в `vendor/bootstrap/LICENSE`. Установка пакетов и сборка не нужны, сайт работает без интернета.

## Самостоятельные доработки

Учебная разметка практик №9–11 и исходный `css/custom.css` сохранены. Пути к Bootstrap заменены на локальные по дополнительному заданию. Собственные блоки отмечены комментариями, стили и небольшой скрипт находятся в отдельных файлах.

- Bootstrap подключён локально вместе с JS Bundle.
- На главной добавлен раздел «Как оформить заявку» из трёх шагов.
- На странице товара добавлены две Bootstrap-вкладки с подсказками и переходом к форме. Для их работы достаточно `data-bs-toggle="tab"`.
- После корректного заполнения любой формы появляется Bootstrap Toast. Данные не отправляются на сервер, поля очищаются. Кнопка исходного модального окна подключена к форме через JavaScript без изменения выданной разметки.
- В `css/extra.css` добавлены единые границы карточек, перенос кнопок, расположение заголовков на телефоне и прокрутка содержимого модального окна на низких экранах.
- Сайт опубликован на GitHub Pages из ветки `main`, папки `/`.

## Запуск и проверка

Откройте `index.html` в браузере или через **Open in Integrated Browser** в VS Code. Можно использовать Live Server. Ссылка на опубликованный сайт находится в начале README.

1. Откройте все четыре страницы, проверьте ссылки меню и выпадающий список.
2. В DevTools проверьте ширины **375, 768, 1024 и 1440 px**. Товары должны перестраиваться в одну, две и три колонки, меню — сворачиваться на узком экране.
3. В каталоге откройте заявку и закройте её крестиком, кнопкой «Закрыть» и клавишей `Esc`.
4. Попробуйте отправить пустые формы. На странице заявки проверьте неверный e-mail и кнопку «Очистить». После корректного заполнения должен появиться Toast без перезагрузки страницы.
5. На странице товара проверьте оба вопроса Accordion и переключение вкладок.
6. Отключите интернет: стили и компоненты должны продолжать работать.

## Результаты проверки

- В VS Code открыты учебный код и страницы, в DevTools проверена сетка каталога на ширинах 375, 768, 1024 и 1440 px.
- Дополнительно в Chromium без доступа к сети проверены все четыре страницы на этих ширинах: горизонтальной прокрутки нет, карточки перестраиваются в одну, две и три колонки.
- Работают мобильное и выпадающее меню, Accordion, вкладки, три способа закрытия модального окна, обе формы, очистка полей и Toast. Пустые обязательные поля и неверный e-mail блокируют отправку.
- Ошибок и предупреждений JavaScript, внешних сетевых запросов не обнаружено. Модальное окно помещается также на экране 375 × 500 px.
- Сверка с сохранённой основой практик подтвердила сохранность учебной разметки и исходного CSS. Файлы из `files_practice` не изменялись.

## Особенности учебного проекта

Товары демонстрационные. Как в образцах практик, все ссылки «Подробнее» ведут на одну страницу товара. Изображения заменены блоками-заглушками. Проверка обязательных полей и e-mail выполняется браузером; отдельной проверки формата телефона нет.

Backend не подключён. Формы показывают учебное уведомление и не отправляют данные на сервер. Поиск, сортировка, корзина и личный кабинет не реализованы.
